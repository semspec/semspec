Derive condition status from fresh test reports and declared source fingerprints, through an evidence port with one adapter for each report format. The core library holds the types of the port and the rule that joins results to checks. The profile key `evidence` sets the adapters (JUnit and Vitest JSON), the check types that each one answers, and a key rule for each: class and method, file and name, or file and title path with a separator. The profile key `verification` stays valid as the JUnit adapter with the key rule class and method, a record of version 1 still loads, and a record of an unknown version makes the evidence stale with a warning. The JUnit adapter reads the reports of JUnit, node test, cargo nextest and the JUnit reporters of Playwright and Vitest. The Vitest adapter reads the JSON report and builds the key from the list of titles. A condition keeps its authored status and gets a derived status in its own field. The roll-up, the gates and the default display use the derived status when the profile has evidence, and the details panel shows both when they differ. `semspec coverage` and the MCP tool coverage count both statuses, the conditions where they differ and the stale conditions, and the option `--status-source` (input `statusSource`) selects the status that the filters, the groups and the gate use. Add native snapshot and collection commands, and expose passed, failed, not-run and stale evidence through graph loads.
