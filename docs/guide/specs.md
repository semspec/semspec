The command `semspec spec` writes specification documents in Markdown from the graph. The author owns the document. Semspec owns the marked sections of it.

An author writes a template. The template is a Markdown file with text of the author and marked sections. The command fills each marked section from the graph. It never changes a byte outside the sections.

## The model

A section starts with a start marker and ends with an end marker. Both markers are HTML comments, so a Markdown renderer does not show them.

```md
# Checkout

The author writes this introduction.

<!-- semspec:section shape=tree scope=area-core self=no -->
<!-- semspec:end -->
```

After `semspec spec checkout.md`, the file holds this:

```md
# Checkout

The author writes this introduction.

<!-- semspec:section shape=tree scope=area-core self=no -->
<!-- generated by semspec; do not edit this section -->

## <a id="item-a"></a>Alpha

...
<!-- semspec:end -->
```

These rules hold for every section:

- The command replaces the text between the markers. The text before, between and after the sections stays byte for byte.
- Each filled section starts with a line that names the generator. The line holds no version, so a new version of Semspec changes no file. The line says not to edit the section.
- The output has a stable order and no time. A second run on an unchanged graph changes no byte.
- A marker inside a fenced code block is text of the author. Use a code block to show a marker in a guide.
- The command writes `\r\n` line breaks in a file that already uses them.
- An error names the file and the line. The command writes no file when one section has an error.

## Markers

A marker has options of the form `name=value`. A value is a word, or text in single or double quotes. A list option takes values that a comma separates, for example `kinds=story,epic`. The option `empty` takes 1 text, and a comma in it is part of the text.

The marker `semspec:node` inserts 1 node into the text of the author. It takes `id`, `graph`, `show`, `level` and `conditions`. It shows the node as a tree section with no node below it.

```md
<!-- semspec:node id=story-pay-by-card show=statement,conditions level=3 -->
<!-- semspec:end -->
```

An unknown option, an unknown node id, an unknown preset, a marker that is not closed, an end marker with no start and a marker inside a marker are errors.

## Select the nodes

These options choose the nodes. They use the rules of the filters of the explorer.

| Option | Meaning |
| --- | --- |
| `graph` | The id of the graph. The default is the first graph of the workspace. |
| `scope` | The node and everything below it. With `depth`, only that many levels. `self=no` leaves the node out. |
| `kinds` | Node kinds. Without it, a section lists the nodes of the hierarchy kinds. A glossary also lists the linked kinds. The gaps shape lists all kinds. |
| `lifecycle` | Lifecycle values. |
| `status` | Status values of the profile, or their labels. A node with no status of its own has the roll-up of the nodes below it. |
| `priority` | Values of the level field of the profile (`fields.level`), when the profile has no field filter named `priority`. |
| `delivery`, `marker` | Delivery values, and provenance markers. |
| `ids` | Node ids. |
| a field filter | Any field of `fieldFilters` in the profile is an option with that name, for example `area=cli`. A value is a code or the label of the code. |

## Shapes

The option `shape` sets what the section writes. The default is `list`.

**tree** writes a heading for each node, in the order of the tree, and the parts that `show` names below it. `level` sets the first heading level, and each level of the tree adds 1.

```md
## <a id="area-core"></a>Core

The core area.

### <a id="item-a"></a>Alpha

Does a thing.

**Steps**

- <a id="item-a#s1"></a>`s1` (Done): First step
- <a id="item-a#s2"></a>`s2` (To do): Second step
```

**list** writes 1 bullet for each node with its statement. Other parts of the node are bullets below it.

```md
- <a id="item-b"></a>**Beta**: The beta item.
- <a id="note-1"></a>**Note one**: A note.
```

**table** writes 1 row for each node. The option `columns` names the columns. The names are `id`, `title`, `kind`, `lifecycle`, `status`, `statement`, `delivery`, `level` and `parent`. Any other name is a field of the node. The default is `id,title,kind,lifecycle,status`.

```md
| Id | Title | Kind | Lifecycle | State of work |
| --- | --- | --- | --- | --- |
| <a id="item-a"></a>`item-a` | Alpha | Item | live | Partly done |
```

**traceability** writes 1 row for each part of the selected nodes, with its status and its checks. The headers come from the profile. The column names are `requirement`, `id`, `condition`, `key`, `status` and `tests`. The default is `requirement,condition,status,tests`.

```md
| Item | Step | State of work | Runs |
| --- | --- | --- | --- |
| <a id="item-a"></a>Alpha | `s1` First step | Done | Runs the first step |
| Alpha | `s2` Second step | To do | No run. |
```

**glossary** writes a heading for each node that has a statement, in alphabetical order. A line below it lists the words of the profile key `search.synonymFields`. With `vocabulary=<id>`, it writes the concepts of a vocabulary instead, with their definitions and alternative labels.

```md
## <a id="item-a"></a>Alpha

Does a thing.

Also called: First, Alpha one
```

**gaps** lists what is open. It has a heading for each kind of gap that exists: the nodes whose status is not good, the parts with no check, the missing deliverables, the nodes that are not placed, the nodes with no source, the unresolved links and the broken cross links. `empty` is the text when no gap exists.

```md
## State of work is not Done

- [`item-a#s2`](#item-a) (To do): Second step

## Without runs

- [`item-a#s2`](#item-a): Second step
```

## Show, sort and shape the detail

| Option | Meaning |
| --- | --- |
| `show` | The parts of a node, as a list: `statement`, `fields`, `conditions`, `tests`, `links`, `crosslinks` and `provenance`. The default is `statement,conditions` for a tree, and `statement` for a list and a glossary. |
| `conditions` | `list` (the default) or `table`. How the parts of a node show in a tree or a list. |
| `depth` | The levels below the first nodes. In a tree, the first nodes are level 0. |
| `sort` | `model` (the default), `id`, `title`, `kind`, `lifecycle`, `status` or `ids`. A glossary sorts by `title`. The sort is stable: equal nodes keep the order of the graph. |
| `level` | The heading level of the first heading, from 1 to 6. The default is 2. |
| `empty` | The text of a section with no node. The default is no text. |

## Labels, anchors and links

A coded value shows the label of its vocabulary. A kind shows its label from the profile. An edge shows the label for its direction. A field filter shows the label of the field.

Each node heading has an anchor `<a id="<node id>"></a>`. A link between nodes of 1 document is `#<node id>`. The anchor works in every Markdown renderer.

A link to a node that another file of the same run holds is a relative link to that file, for example `../glossary.md#pay-card`. When no file of the run holds the node, the text shows the title and the id in code. The cross links of the profile work the same way, also into other graphs of a workspace.

A value is plain text. Semspec escapes the characters that Markdown reads, and the pipes of a table. A cell holds 1 line. A long text ends with an ellipsis.

## Presets

A profile names sets of options. A marker takes a set with `use=<name>`. The options of the marker win over the set.

```yaml
spec:
  presets:
    open: { shape: table, status: [partial, open], columns: [id, title, status] }
```

```md
<!-- semspec:section use=open kinds=requirement -->
<!-- semspec:end -->
```

A set can name any option of a section, except `use`. A list value is a YAML list or a text with commas. The profile check fails on an unknown option in a set.

## Default documents

Without a template, the command writes 1 document for each root node.

```
semspec spec --workspace workspace.yaml --out docs/spec
semspec spec --graph graph --profile profile.yaml --out docs/spec --roots product --glossary graph
```

The root kinds come from `spec.roots` in the profile, or from `--roots`. A document has the title of the node, a line for the introduction, a tree section and a traceability section. The file name is the node id. `--glossary <graph id>` also writes a glossary document for 1 graph. Its file is `glossary.md`, or `glossary-<graph id>.md` in a workspace.

A default document is a template like any other. When the file exists, the command keeps all its text and fills only the marked sections. Write your introduction in the file, and change the options of the markers. Links from the other documents point to the anchors of the glossary.

## Check in CI

`--check` writes nothing. It exits with 0 when every section matches the graph, and with 1 when a section is stale or an author changed it. A stale section is a section that the graph no longer gives. The message names the file, the line and the section.

```
semspec spec --graph requirements/graph --profile requirements/profile.yaml docs/requirements.md --check
```

`--json` prints `{ "ok", "findings", "written", "sections" }`. See [Gates](gates.md) for a CI workflow, and [Command line](../reference/cli.md) for all options.

A header with a version, written by an older Semspec, still counts as the same header.
