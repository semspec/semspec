### <a id="cap-spec-sections"></a>Generated sections in a Markdown template

A Markdown template holds author text and marked sections. The spec command fills each marked section from the graph and keeps the author text.

#### <a id="req-spec-check"></a>Fail when a spec is stale

The spec command with --check writes nothing and fails when a filled section differs from what the graph gives.

**Acceptance**

- <a id="req-spec-check#stale"></a>`stale` (Verified): With --check, a section that differs from the graph makes the command exit with a code other than 0 and names the file and the section.
- <a id="req-spec-check#edited"></a>`edited` (Verified): A section that an author changed by hand fails --check the same way.
- <a id="req-spec-check#clean"></a>`clean` (Verified): With --check on up-to-date files, the command exits 0 and changes no file.
- <a id="req-spec-check#gate"></a>`gate` (Verified): The guide for gates shows how CI runs the spec check.

#### <a id="req-spec-default"></a>Write default documents with no template

Without a template, the spec command writes 1 document for each root node that the profile names, with the same section engine.

**Acceptance**

- <a id="req-spec-default#per-root"></a>`per-root` (Verified): The command with --out writes 1 Markdown file for each root node of the kinds that the profile or an option names, with a tree section and a traceability section.
- <a id="req-spec-default#same-engine"></a>`same-engine` (Verified): A default document is a template with generated sections, so a second run with --check passes.
- <a id="req-spec-default#glossary-doc"></a>`glossary-doc` (Verified): In a workspace, the command can write 1 glossary document for a graph, and cross links from other documents point to its anchors.

#### <a id="req-spec-markers"></a>Fill the marked sections of a template in place

The spec command rewrites only the content between a start marker and an end marker, and keeps every other line of the file.

**Acceptance**

- <a id="req-spec-markers#markers"></a>`markers` (Verified): A section starts with the HTML comment \`&lt;!-- semspec:section ... --&gt;\` and ends with \`&lt;!-- semspec:end --&gt;\`. The markers do not show when the Markdown is rendered.
- <a id="req-spec-markers#in-place"></a>`in-place` (Verified): The command replaces the content between the markers and keeps the author text before, between and after the sections, byte for byte.
- <a id="req-spec-markers#idempotent"></a>`idempotent` (Verified): A second run on an unchanged graph changes no byte of the file.
- <a id="req-spec-markers#deterministic"></a>`deterministic` (Verified): The output has a stable order and holds no build time, so a diff shows only changes of the graph.
- <a id="req-spec-markers#header"></a>`header` (Verified): Each filled section holds a short line that names the generator and says not to edit the section.
- <a id="req-spec-markers#errors"></a>`errors` (Verified): An unknown option, an unknown node id, a marker that is not closed or a nested marker is an error that names the file and the line.
- <a id="req-spec-markers#node-marker"></a>`node-marker` (Verified): The marker \`&lt;!-- semspec:node id=... --&gt;\` with its end marker inserts 1 node in the text of the author.

#### <a id="req-spec-options"></a>Select and shape the content of a section

The options of a section marker select the nodes and set the shape, the detail and the heading level of the content.

**Acceptance**

- <a id="req-spec-options#select"></a>`select` (Verified): The options graph, scope, kinds, lifecycle, status, priority, ids and any field filter of the profile select the nodes, with the same rules as the filters of the app.
- <a id="req-spec-options#shapes"></a>`shapes` (Verified): The option shape takes tree, list, table, traceability, glossary or gaps, and each shape writes valid Markdown.
- <a id="req-spec-options#detail"></a>`detail` (Verified): The option show selects the parts of a node: statement, fields, conditions, tests, links, cross links and provenance. The option depth limits a tree, and sort sets the order.
- <a id="req-spec-options#level"></a>`level` (Verified): The option level sets the heading level of the first heading of the section, so the section fits under a heading of the author.
- <a id="req-spec-options#empty"></a>`empty` (Verified): The option empty sets the text of a section whose selection is empty.
- <a id="req-spec-options#labels"></a>`labels` (Verified): Coded values show their vocabulary labels, and kinds and edges show their labels from the profile.
- <a id="req-spec-options#anchors"></a>`anchors` (Verified): Each node heading has an anchor equal to the node id, and links between nodes in the same document use these anchors.
- <a id="req-spec-options#cross-links"></a>`cross-links` (Verified): A link to a node of another graph or another document is a relative Markdown link when that node has a generated document, else plain text with the id.
- <a id="req-spec-options#columns"></a>`columns` (Verified): For shape table and shape traceability, the option columns names the columns and their order. A cell shows a short value in 1 line, and a long text is cut with an ellipsis.
- <a id="req-spec-options#conditions-form"></a>`conditions-form` (Verified): The option conditions takes list or table and sets how the acceptance conditions of each node show, apart from the shape of the section.

#### <a id="req-spec-presets"></a>Name section presets in the profile

The profile defines named section presets, and a marker uses a preset by name and can override its options.

**Acceptance**

- <a id="req-spec-presets#profile-key"></a>`profile-key` (Verified): The profile schema has a key for named section presets with the options of a marker.
- <a id="req-spec-presets#use"></a>`use` (Verified): A marker with \`use=&lt;name&gt;\` takes the options of the preset, and its own options win over them.
- <a id="req-spec-presets#unknown"></a>`unknown` (Verified): A marker that uses an unknown preset is an error that names the file and the line.
